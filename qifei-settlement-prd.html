1. 背景与目标

祈飞业务的结算分两条链路：

  • 商品维度：财务维护一批「参与祈飞结算」的商品，并给每个商品设定结算有效期，订单创建时间落在有效期内才参与结算。
  • 达人维度：祈飞作为货主去找达人带货（达播），需要按「达人 × 商品」维护带货关系与佣金率，同样受结算有效期约束。

目标：让财务在一个后台里完成上述两类结算对象的建档、有效期管理与终止，减少线下表格维护带来的错漏。

截断语义（本次修改 = 修改「生效日期至今」的通用佣金率）：保存新记录时，先删除所有生效日期 ≥ 新生效日期的既有记录，再追加新记录，按生效日期升序排列——即新记录「接管」其生效日期起的所有后续区间。

保存后编辑弹窗关闭、历史变更记录弹窗重新打开并刷新表格、卡片即时刷新（展示最新生效的费率），toast「通用佣金率已保存」。关闭方式：各弹窗右上 ×、按钮、点遮罩。

通用佣金率随时间变化：按「生效日期」形成记录链——某一天生效的通用费率 = 「生效日期 ≤ 该天」且生效日期最新的一条记录；商品渠道留空时，取该订单结算时间点对应的通用费率。

兜底规则：商品的某个渠道没有配置指定规则时，按该渠道的通用佣金率结算。

说明：原「祈飞结算商品范围（全店商品 / 指定商品）」开关已移除。在新模型下「未配置规则的商品 = 按通用佣金率结算」，与「全店商品」语义完全重叠，保留反而会出现"切到全店后商品列表被隐藏、规则无处维护"的死角。

4.2 佣金规则模型（核心）

一条「结算规则」= 一个结算时间段 + 该时段内的 5 个渠道费率（v1.22.0：渠道为 直播（默认）/ 短视频 / 商品卡 / 推荐卡 / 其他，仍是一条规则带多个渠道，不按渠道拆成多条）。

结算类型（弹窗内单选切换，二选一）：

类型 字段 结算行为
指定佣金结算（默认） 结算时间 + 5 个渠道费率（直播（默认）/ 短视频 / 商品卡 / 推荐卡 / 其他） 按费率结算
不参与结算（剔除） 只填结算时间（留空 = 长期剔除） 命中即不结算，不再往下匹配；费率字段隐藏
要素 说明
结算时间 开始时间（必填）～ 结束时间（留空 = 长期），两种类型都填
直播（默认）佣金率 可编辑，默认带出该渠道通用佣金率；留空 = 按通用佣金率结算（仅「指定佣金结算」类型）
短视频 / 商品卡 / 推荐卡 / 其他佣金率 同上，每个渠道各自独立，留空各自取通用值（仅「指定佣金结算」类型）

剔除粒度 = 整个商品：命中剔除规则时，该商品全部 5 个渠道的订单都不参与结算（不支持只剔单个渠道）。

规则约束：

  1. 唯一性：同一商品同一结算时间段内只允许一条规则（时间段重叠即冲突，保存时拦截「该商品在该时间段内已存在结算规则」）。
  2. 与通用一致不新增：保存时若5 个渠道费率全部与各自通用佣金率一致（或都留空），直接提醒「该规则的佣金率与通用佣金率一致，无需单独指定」，不新增 / 不保存该条规则。
  3. 留空 = 按通用佣金率结算（不是"不结算"）。

匹配与结算（命中即止，逐层降级）：

  1. 订单创建时间落在某条不参与结算规则的结算时间段内 → 不结算（优先级最高）。
  2. 落在某条指定佣金结算规则内 → 按该规则的渠道费率结算；该渠道留空则取通用佣金率。
  3. 未落在任何规则内 → 按通用佣金率结算。
  4. 规则被修改（费率 / 时间段 / 结束结算）后，对该规则影响时间范围内的订单重新计算。

规则状态（按「今天」判定）：

状态 判定
待开始 今天 < 结算开始时间
生效中 结算开始时间 ≤ 今天 ≤ 结算结束时间（结束为空视为长期）
已结束 今天 > 结算结束时间

8. 状态与数据规则

  • 状态取值：生效中 / 已结束（无「草稿」「停用」）。
  • 状态计算：结算结束时间 ≤ 当天 → 已结束；否则生效中。结束时间为「永久」时恒为生效中（仅商品维护页允许永久）。
  • 更新人 / 更新时间：任何一次保存（新增、编辑、结束结算、合作信息、带货商品）都会刷新为当前操作人与当前时间。
  • 有效期判定口径：订单创建时间落在 结算开始时间 ≤ 订单创建时间 ≤ 结算结束时间 内才参与结算。注意创建时间与支付时间是两个概念，此处以创建时间为准（下单时点），不以支付成功时点。
  • 列表排序（两个列表通用）：状态优先级 生效中(0) < 已结束(1)，同级按更新时间倒序；因此「结束结算」后该行会自动下沉到已结束区。
  • 商品维护与达播结算互相独立：同一商品可同时存在于两条链路，有效期与佣金率分别维护。
